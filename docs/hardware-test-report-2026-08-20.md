## 1. 测试目标

验证 Auto.js6 工程能否在真实 KARDS 运行环境中完成以下链路：

1. 连接模拟器并获取游戏截图；
2. 识别当前页面、回合、手牌和单位；
3. 从现有界面导航至新对局；
4. 验证自动点击、出牌、攻击、结束回合和结算流程。

## 7. 问题清单

### P0：导航模板误匹配

`autodrive.js` 当前使用全屏 `images.findImage` 搜索菜单模板。战场中存在外观相似区域，导致：

- `home-start.png` 命中非主菜单区域；
- `mode-training-unselected.png` 命中非模式菜单区域。

**影响**：可能对错误位置产生触控，不能用于自动导航。

### P0：导航缺少页面前置条件

脚本未在点击开始、训练模式前强制确认当前页面分别是：

- `HOME`；
- `MODE_MENU`；
- `DECK_LIST`；
- `DECK_DETAIL`。

**影响**：从错误页面启动时仍继续点击。

### P0：点击后缺少状态变化验证

点击后仅等待固定时间，没有验证：

- 页面是否发生变化；
- 模板是否移动到预期区域；
- 页面分类是否进入目标页面。

**影响**：点击无效或误点击时，脚本仍继续下一步。

### P1：KARDS 网络稳定性

此前实机记录显示游戏曾多次出现断开连接和重连弹窗。该问题会阻止稳定进入匹配和对局，需与脚本问题分开排查。

## 8. 当前安全结论

当前 Auto.js 工程可以安全执行观察和识别，但不能宣称已完成自动对战。

当前明确结论：

- **识别链路：通过**；
- **模板匹配基础能力：通过，但跨页面误匹配风险高**；
- **自动导航：失败**；
- **新对局进入：未验证通过**；
- **自动出牌：未验证**；
- **自动攻击：未验证**；
- **自动结束回合：未验证**；
- **完整对战闭环：未实现/未验证**。

配置应继续保持观察模式，直到导航修复并完成逐步验证。

## 12. 续测记录（同日）

## 14. 空闲退出与坐标计算续测

本轮静态 OCR 探针在真实对局中保持无动作，KARDS 因长期不活跃自动退出。该现象属于测试流程问题，不是截图权限失效。已采取两项措施：

- `autojs/main.js` 启动时调用 `app.launchPackage(config.kardsPackage)`，把 KARDS 拉回前台后再申请截图，避免 Auto.js 运行器遮挡游戏；
- 后续实机动作测试必须使用有明确结束条件的短脚本，禁止把静态探针长时间挂在对局中。

手牌坐标采用“屏幕尺寸归一化 + 手牌数量校准”的计算方式：先由左侧锚点和连续探针确定数量，再按数量计算卡牌间距和边界，最后乘以当前屏幕宽高换算像素。这样可适配分辨率变化；扇形透视仍保留 1–9 张的校准锚点，避免用单一直线公式造成低数量手牌偏移。

本次进一步复核发现，当前实机版本的“结束回合”按钮位于右侧中部（约 `[1055,488]–[1242,544]`，1280×720），不是旧记录中的右下角。已同步修正 `endTurnUi`、`targetSlots.end-turn`、驱动坐标，并新增 `battle-turn-ours-current.png` 模板限制在该区域搜索。实机手动触控验证后，按钮由橙色“结束回合”切换为灰色“敌方”，说明新坐标有效；旧 `battle-turn-ours.png` 保留用于历史截图回放测试。

同时修正了回合页误判：商店宣传卡不再触发结束回合模板，战场淡入帧使用右侧按钮区域和棋盘特征联合确认；扇形手牌的左右位置也不再被当作卡牌优先级，费用排序注释已改为“显式优先级优先，费用仅作次级排序”。

右侧按钮颜色也纳入回合判定：橙色才允许识别为我方回合，白/灰色识别为敌方回合。Auto.js6 单帧实机回放已得到 `BATTLE / OPPONENT_TURN / grey-end-turn`，不再把敌方回合误当成可操作回合。

随后在无浮层的 6 张手牌帧中，费用探针稳定读到中间四张 `4、3、4、3`；左右边缘费用因扇形裁切暂不采信。费用为 0 且没有可出牌卡时，限时动作测试成功点击结束回合，截图中的按钮由橙色切换为灰色“结束回合/敌方”，并观察到敌方单位更新。真正的拖牌出牌仍需等待一张费用已确认且可负担的卡牌后再做实机验证。

## 15. 出牌失败后的回合处理修正

离线回放发现，单次拖牌未被画面确认时，旧逻辑会立即把整回合标记为跳过；这会表现为“脚本只是一味结束回合”。现已改为：

- 将未确认的卡牌加入本回合失败列表，不再重复拖同一张牌；
- 继续尝试其他费用和可出状态均已确认的卡牌；
- 本回合达到有界出牌尝试上限后，才允许安全结束回合；
- 决策树在候选牌全部被隔离时回退到单位操作或结束回合，不再产生无动作 PLAY_CARD 空转。

新增 `runtime-replay.test.js` 回放断言已覆盖“第一张拖拽失败 → 尝试第二张 → 全部失败后才结束回合”。当前实机动作探针仍处在对手回合（灰色结束回合按钮），8 秒有界测试未发出战斗动作；Auto.js 已停止，未留下长期空转脚本。

## 16. 总部目标区域校准

坐标网格复核发现旧 `targetSlots` 的总部区域已经落在顶部 HUD 和底部手牌扇形：敌方总部变化值只有 `0.106`，低于合法目标阈值 `0.16`；我方总部区域还会被手牌变化污染。现已改为：

- 敌方总部：`[0.40, 0.10, 0.60, 0.40]`
- 我方总部：`[0.40, 0.60, 0.60, 0.90]`

真实截图前后帧回放显示，修正后 `enemy-hq` 能进入合法目标列表；`runtime-replay.test.js` 已加入该断言。攻击实机动作仍需在我方单位可操作且目标高亮的回合单独验证。

另外，运行时现在会在回合切换时清除未完成的卡牌/单位动作握手，避免上一回合的 `pending` 源牌或目标泄漏到下一回合。

## 17. 中心单位槽位与总部误报修正

- 将中心前排槽扩展到真实单位边缘，并将己方中心前排下边界收至 `0.60`；

`post-action-test-now.png` 回放结果从“我方单位 1（实际为空）”修正为“我方单位 0、敌方单位 2”；`vision-replay.test.js` 已加入该安全断言。
