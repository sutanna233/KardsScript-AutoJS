# 视觉与指向性实现说明

## 不训练模型的实现

视觉层分为独立、可替换的组件：

1. `LayoutCalibrator` 用稳定 UI 锚点建立屏幕归一化坐标到像素的映射；每个设备、语言和画质保存一个配置档案。
2. `SceneClassifier` 结合结束回合/继续/重连等 UI 模板、OCR 和区域特征输出场景。
3. `SlotDetector` 对支援线、前线和手牌区域进行轮廓、背景差分和卡框几何检测。
4. `OcrRecognizer` 读取卡名、Kredit、总部生命和攻防数值；卡名通过导入卡组词典做纠错。
5. `VisualDiff` 在选择某张卡或单位前后比较每个槽位的亮度、HSV 饱和度、边缘强度和模板残差。

## 指向性

`VisionGateway.probeLegalTargets()` 是唯一产生合法目标的接口：

- 先缓存选择前稳定帧；
- 自动化层选中单位或牌；
- 等待稳定帧，视觉层计算候选槽位的视觉变化；
- 返回带置信度的 `TargetCandidate` 列表；
- `DecisionTreeInterpreter` 只在 `PendingInteraction.legalTargets` 内排序，不能凭空生成点击坐标。

因此，新增带目标卡牌不要求先补全规则库；只要游戏在选中后给出目标高亮，目标探测就能适配。

## 配置档案

配置档案按以下键保存：`设备尺寸 + dpi + 横竖屏 + 游戏语言 + 画质 + UI版本`。找不到精确档案时使用锚点实时校准，并将通过验证的结果保存为新档案。
